El pin público de captura no sustituye el ámbito completo del diario. Prueba paginación completa e incompleta, permisos insuficientes, fuente ausente o vieja, respuesta truncada, límite de bytes, timeout, rate limit y pérdida de acceso. Una página vacía no demuestra cobertura completa si faltan páginas. No inventes una relación por igualdad de ID o nombre entre proveedores.

Entrega una matriz de capacidades implementadas, simuladas y pendientes de ensayo real. Si haces un transporte de solo lectura, acota host, método, rutas, redirecciones, tiempo y presupuesto; no incluyas un transporte genérico capaz de escribir. Las pruebas no imprimirán credenciales ni cuerpos sensibles. Una prueba sintética acredita implementación, no acceso al proveedor.

## Cómo mantener una sesión productiva

Después de presentar un paquete, toma otro independiente mientras se revisa. Puedes alternar QA, adaptación Zendesk, adaptación Pipedrive, fixtures y motor de migración; cada uno tiene sus reservas y límites. No uses una dependencia pendiente para abandonar todos los demás. Tampoco fuerces una puerta de aceptación ni crees un número obligatorio de pruebas para aparentar progreso.

Cada entrega identifica qué llegó a la App, qué es interno, qué espera montaje y la unidad responsable. Entrega al dueño del contexto el registro con fecha, verificación y siguiente paso si su archivo sigue reservado. Termina con una demostración breve de valor y una tabla de capacidad → entrada → API → efecto → evidencia → dueño. No declares actividad continua después de cerrar la sesión.

Todo este encargo usa este equipo y ficción nueva. No autoriza producción, escrituras a proveedores, acceso corporativo, lectura de perfiles o credenciales, commits ni despliegues. Si la fase externa sigue sin autorización, déjala pendiente y continúa el desarrollo local útil.
